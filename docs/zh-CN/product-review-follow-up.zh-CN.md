# 2026 年 11 月产品评审：后续依赖

[English](../product-review-follow-up.md) | 简体中文

本页用于维护者规划，不是已承诺的发布日程。本次实施 P0 01–04。评审中的下载量
和竞品数据作为用户提供的快照，尚未独立核实。实施时 GitHub About 已有定位句，
README 已有终端动图，因此保留并改善现有成果。

| 条目 | 依赖与下一项可评审交付物 | 验收证据 |
| --- | --- | --- |
| 05 声明式 apply | 依赖 03 预设及 09 密钥引用。先规定密钥解析、逐 Agent patch、全部目标预检、脱敏 diff 和部分失败，再实现 `ccset.toml`；仍作为 P1 首要产品目标。 | 同一供应商扇出三个 Agent；dry-run 零写入；最后一个目标损坏时前面也不能写。 |
| 06 协议探测 | 复用主机确认、拒绝重定向和丢弃响应体；明确 Messages、Responses、Grok 各协议请求及超时／认证／协议错误码，脚本确认必须显式指定主机。opencode 的 SDK 映射明确前保持不支持。 | mock server 覆盖认证失败、超时、协议错误、重定向及输出无密钥／响应体；真实兼容性另记。 |
| 07 备份生命周期 | 先复用清理核心规定 `backups clear`，与 08 删除确认、09 凭据来源协调。决定轮换清理是否 opt-in、过期时如何保留最后一个可恢复原件；本次不自动删除恢复证据。 | 按时间筛选、dry-run、部分清理失败，以及使用占位凭据的轮换／回退测试。 |
| 08 脚本生命周期 | list/show 复用状态 DTO，删除复用已有 provider-removal。扩展 ADR 0007/0019，规定 `--yes`、dry-run、所有 Agent 的当前供应商检查、忽略项可见性及整文件／共享块删除。 | 脚本完成新增→查看→切换→删除→备份清理；在用目标不可删；密钥仅显示有无。 |
| 09 密钥引用 | 明确字面密钥与引用、`--token-env` 冲突、unset、变量缺失及 Agent 原生优先级。同步修改 Codex env_key 拒绝规则、Grok 非托管规则、manifest 和共享预检。 | 引用往返不落密钥正文；不支持的 Agent 写前拒绝；切换不能启用过时的内联凭据。 |
| 10 Agent 接入 | 先核实 Gemini 的真实需求和公开自定义 endpoint 契约。用户场景、可重复 fixture 是门槛；强制先有外部 issue 与现行贡献政策冲突，需要明确政策决策。 | 外部使用场景、格式 fixture 与维护证据；不单因竞品清单新增 Agent。 |
| 11 安装分发 | 独立核实 npm 名称所有权／可用性、v0.10.0 实际可安装性及 Release 正文，再修改发布说明。单文件／Homebrew 需要供应链、平台、更新及运行时方案。 | 干净环境安装与产物检查；记录一次原生 Windows 交互实测。 |
| 12 预设分发 | 依赖 03 发布；多 Agent dotfiles 还依赖 05/09。用已发布命令和环境密钥编写可执行的 devcontainer、CI、dotfiles、远程开发 recipe。 | 隔离环境执行 recipe；获得搜索证据后再统计外部使用。 |
| 13 文档分层 | 用 02/04 统一动词组织任务 recipe；搬迁参考内容时维护锚点及双语链接。比较页需要当前一手证据，并明确何时适合 cc-switch。 | 链接／搜索检查、可执行示例，以及无需读长参考即可完成首次切换。 |

建议先确定 09，再基于它交付 05；随后做 08 和 07。06 可以独立推进，12 跟随预设
发布；10–11 需要外部证据或权限；13 随各流程交付逐步推进。十份备份保留、TUI
删除入口和现有探测覆盖仍是当前实际行为，直到相应条目完成。
