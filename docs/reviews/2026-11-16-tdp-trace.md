## Distinguish requirements from implemented guarantees

- F3 parse-failure exit 4 is implemented: [status findings](../../src/agents/claude-code/status-dto.ts) feed [presentSuccess](../../src/commands/run.ts), which returns `EXIT_INVALID_CONFIG` while retaining readable sections.
- Managed token omission is implemented; complete URL/unmanaged-metadata secrecy is not. [Claude DTO](../../src/agents/claude-code/status-dto.ts), [Codex DTO](../../src/agents/codex/status-dto.ts) and [pi DTO](../../src/agents/pi/status-dto.ts) still expose values identified in [review B-2/B-3](../../review.md#open-findings).
- Fresh form/save reads do not provide a transaction or concurrent-writer protection. [applyPlan](../../src/operations/commit.ts) performs ordered per-file writes; [backup name selection](../../src/core/backup.ts) remains existence-based before rename (review B-4/B-5).
- Ten-backup retention is a limit attempted by [pruneBackups](../../src/core/backup.ts), which swallows unlink failures; it is not an unconditional successful-pruning guarantee. Explicit `clearBackups` reports completed removals and failures.
- Published scoped 0.11.1 is recorded in §9.78; unscoped registration was still pending there. A version-matched package/guard/workflow does not prove publication.
- Existing Codecs and local checks do not establish live upstream compatibility. The register's U1–U4/U6/U8–U10 remain bounded upstream questions, not claims that these local integrations are missing.
